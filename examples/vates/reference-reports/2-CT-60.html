Resolved-case template CT-60: Xen Orchestra cannot connect to a pool after its host certificate was replaced (TLS error) (synthetic scenario - not a resolved case): Xen Orchestra Improving security in Xen Orchestra (seen 2026-10-10); Xen Orchestra Troubleshooting - Xen Orchestra docs (seen 2026-10-10)
Cause: Per the summaries: since a 5.8.x release XO refuses to connect to a host whose certificate is invalid (self-signed or expired) unless that is explicitly allowed; the XCP-ng hosts own certificates are managed with xe commands on every host of the pool.
  1. Verify the new certificate, then either install a certificate XO trusts on every pool host or accept it via the warning/toggle in the XO server settings.
  2. Plain HTTP also works but sends all traffic unencrypted.
  3. Expired appliance certificate: regenerate cert.pem/key.pem with openssl and restart xo-server (docs summary).
